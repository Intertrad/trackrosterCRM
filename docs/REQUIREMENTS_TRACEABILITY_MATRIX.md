It is the 42-page TrackRoster Product Design Dossier v1.0. The matrix below is derived from that dossier, including its roadmap on p. 37 and its MVP Definition of Done on p. 41. The older proposed baseline is superseded by this matrix.

Evidence labels:

- **PASS** means the latest remediation report records the automated evidence as green.
- **PARTIAL** means some API or worker behavior exists but the dossier acceptance evidence or a required part of the behavior is still open.
- **OPEN** means the requirement is not yet demonstrated to the release standard.
- **E2E OPEN** means component/API tests exist, but the authenticated browser or responsive evidence has not been run.

## Corrected release interpretation

The MVP blockers are the requirements that prevent the p. 41 Definition of Done or the indispensable p. 37 list from being demonstrated: source approval, six-role scope/responsive evidence, import quality, complete notifications including required transactional channels, dashboard dimensions, export artifacts, and full backup/restore. SSO, external webhooks/API, advanced maps, attachments, voice notes, calendar/templates, scheduled reports, and broad load-scale targets do not become MVP blockers merely because the repository has provider hooks for them.
