# Backend implementation status

The user requested every API in API_BUILD_LIST.md (P0, P1 and P2), using the product and design handoff as requirements. Frontend work is deferred. Existing implementations and migrations are preserved. A route is not complete merely because a controller exists: authorization, persistence, business rules, validation, auditing, idempotency and tests must support the intended behavior.

## Verification commands

Start the disposable services with `docker compose -p trackroster-backend-validation -f docker-compose.backend-test.yml up -d --wait`.

- `node scripts/backend-test.mjs migrate` applies the entire chain to the fixed isolated database.
- `node scripts/backend-test.mjs integration` runs API and worker integration tests against isolated PostgreSQL/Redis.
- `node scripts/check-migration-integrity.mjs` validates migration history.
- From `apps/api`, run `./node_modules/.bin/vitest run`, `./node_modules/.bin/tsc --noEmit`, and `./node_modules/.bin/nest build`.
- Run the worker unit suite/typecheck/build from apps/worker.

The test runner never reads the developer database URL and uses only ports 55439/56389. Integration tests create and remove their own fixtures. The test compose data is ephemeral.
